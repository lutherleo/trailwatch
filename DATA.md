# Data

trailwatch ships **no external datasets**. Everything it reads in tests, the demo and the
evaluation is either generated by the bundled simulator or hand-authored. No data is downloaded.

| data | location | source | license | size |
|---|---|---|---|---|
| Synthetic IP -> network map | `src/trailwatch/data/netmap.csv` | hand-authored for this project: reserved address space only (RFC 6598 `100.64.0.0/10`, RFC 2544 `198.18.0.0/15`), private-use ASNs 64512-65534, invented organisation names; latitude/longitude are public city-centre coordinates | MIT (this repository) | 3 KB |
| CloudTrail fixture | `fixtures/cloudtrail/*.json` | hand-authored CloudTrail log file (14 records incl. one malformed and one duplicate) following the public CloudTrail record format; account id `111122223333` is the AWS documentation placeholder | MIT (this repository) | 13 KB |
| Golden alerts | `fixtures/expected-alerts.jsonl` | produced by `trailwatch detect fixtures/cloudtrail` (regenerate with `UPDATE_GOLDEN=1 uv run pytest tests/test_golden.py`) | MIT | 5 KB |
| Simulated accounts | generated on demand (`trailwatch simulate`, `make demo`, `make eval`) | `src/trailwatch/sim/`; deterministic per seed | MIT | ~100k events per 90-day account; nothing committed |
| Evaluation outputs | `eval/heldout.{md,json}`, `eval/tune.md` | produced by `make eval` / `make tune` | MIT | < 20 KB |

## What is synthetic and what is modelled on reality

* **Record format**: modelled on the documented CloudTrail record schema (eventVersion 1.08:
  `userIdentity`, `eventSource`, `eventName`, `sourceIPAddress`, `userAgent`,
  `requestParameters`, `additionalEventData.MFAUsed`, ...). API names are real AWS management API
  names. Field contents (ids, keys, IPs) are random.
* **Behaviour**: invented. Personas, schedules, volumes, travel frequency, VPN usage, scanner
  cadence and attack sequences are modelling assumptions about typical accounts and common
  public descriptions of cloud intrusions (MITRE ATT&CK for IaaS). They are not derived from any
  real organisation's logs.
* **Networks**: invented organisations in reserved ranges; only city coordinates are real.

Because the simulator and the detector are developed together, evaluation numbers measure the
detector against modelled behaviour, not real-world performance (see README "Limitations").
